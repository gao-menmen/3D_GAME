# Project Urban Spear 游戏设计文档

- 日期：2026-07-29
- 状态：已批准，等待仓库文档复核
- 平台：Windows 64 位
- 引擎：Unreal Engine 5，基于 Lyra 模块化多人架构
- 工作代号：Project Urban Spear（城市之矛计划）

> “Project Urban Spear”是项目工作代号。正式发行名称不属于首阶段设计范围，且不会影响架构或内容实施。

## 1. 项目目标

制作一款面向 Windows 的近未来写实 3D 战术射击游戏。游戏以 2035 年的虚构城市冲突为背景，玩家隶属于国际联合特遣队，可在第一人称和第三人称之间切换。

最终产品支持以下玩法：

1. 单机 PVE；
2. 2–4 人合作 PVE；
3. 多人 PvP；
4. 玩家与 AI 同场的综合模式。

首阶段交付一段 30–45 分钟、可独立运行的单机 PVE 完整章节。底层系统从第一天按照多人联网规则设计，以便后续增加合作和 PvP，而不重写角色、枪械、伤害和任务系统。

## 2. 设计原则

### 2.1 核心体验

游戏围绕四个体验支柱设计：

- **战术枪战**：武器具有重量、后坐力和较高伤害，并支持掩体、压制、部位伤害及有限穿透；
- **多路线城市战斗**：街道、商业建筑、屋顶、停车场和地铁形成室内外连续战场；
- **智能敌人**：敌人能够巡逻、搜索、使用掩体、包抄和呼叫增援；
- **模式共享**：单机、合作和 PvP 共用角色、枪械、伤害、物品与任务底层。

### 2.2 战术程度

采用“平衡战术”定位：

- 枪械后坐力和伤害明显；
- 玩家需要观察、侦察、管理弹药和使用掩体；
- 不使用阻碍普通玩家理解和完成任务的过度复杂生存系统；
- 普通难度提供清晰提示和适量补给，战术难度减少提示并提高敌人威胁。

### 2.3 原创性与合规

项目可以参考现代战术射击游戏的类型特征，但必须使用原创世界观、阵营、名称、标识、任务和视觉设计。禁止复制其他游戏的角色、地图、武器皮肤、界面、音效或品牌资产。

## 3. 世界观与玩家身份

故事发生于 2035 年。一座现代城市因关键近未来技术和加密数据的争夺陷入武装冲突。国际联合特遣队进入城市，执行营救、情报回收、据点控制和撤离任务。

主要威胁包括：

- 受雇控制城区的武装人员；
- 精确射手与突击单位；
- 侦察和攻击无人机；
- 自动化防御设备；
- 后续 PvP 阶段中的敌对玩家阵营。

近未来元素以现实可信为边界，包括侦察无人机、智能瞄具、战术扫描和先进通信设备，不引入超能力或魔法式装备。

## 4. 技术路线

### 4.1 引擎选择

采用 Unreal Engine 5，并以 Lyra Starter Game 的模块化多人架构作为基础。选择该方案的原因是：

- 最终目标包含合作和 PvP，需要尽早建立联网边界；
- Lyra 提供模块化游戏功能、角色能力、武器和多人模式参考；
- Unreal 适合高品质写实 3D、角色动画、大型场景和 Windows 打包；
- 蓝图允许快速迭代，C++可承载长期维护的核心规则。

不以 City Sample 作为项目基础。City Sample 仅作为大型城市技术参考，因为它的运行和编辑成本不适合当前开发设备。

### 4.2 C++与蓝图边界

- **C++**：联网权威、角色状态、枪械、伤害、护甲、任务状态、存档接口和通用模块；
- **蓝图**：关卡事件、任务编排、界面连接、特效触发、音频触发和设计师快速调整；
- **数据资产**：武器参数、敌人参数、装备定义、任务定义和难度配置；
- **Game Feature 模块**：根据游戏模式启用或关闭独立功能。

### 4.3 模块划分

- `UrbanCore`：角色、移动、视角、交互、玩家资料和存档；
- `UrbanCombat`：枪械、弹药、配件、伤害、护甲和战术装备；
- `UrbanAI`：感知、状态、掩体、搜索、包抄和增援；
- `UrbanMission`：目标、检查点、失败条件、评分和撤离；
- `UrbanModes`：任务撤离、据点进攻、生存防守与 PvP 规则；
- `UrbanUI`：菜单、HUD、设置、字幕和无障碍功能；
- `UrbanOnline`：合作房间、玩家同步和后续专用服务器接口。

模块通过明确接口通信。游戏模式不得复制角色、枪械或伤害逻辑。

## 5. 角色、视角与移动

### 5.1 视角

PVE 和合作模式允许第一人称与第三人称自由切换。PvP 服务器可以配置为仅第一人称，以避免第三人称观察掩体后方造成不公平优势。

两个视角共享同一个完整角色状态，但表现层分离：

- 第三人称显示完整角色模型和全身动画；
- 第一人称使用适合近距离观察的手臂、武器和摄像机表现；
- 武器、弹药、伤害和交互状态保持一致；
- 第一和第三人称灵敏度可以分别设置。

### 5.2 移动能力

首阶段包含：

- 行走和奔跑；
- 冲刺；
- 蹲伏；
- 跳跃；
- 基础翻越；
- 瞄准移动；
- 受伤与死亡状态。

首阶段不包含贴墙移动、复杂攀爬、滑铲连招和载具驾驶。

## 6. 枪械、伤害与装备

### 6.1 首章武器

首章提供三种武器：

1. **突击步枪**：主要中距离武器，支持单发和自动射击；
2. **冲锋枪**：适合商场、停车场和地铁近距离战斗；
3. **战术手枪**：副武器，用于紧急切换和狭窄空间。

基础配件包括红点或全息瞄具、战术灯、消音器和枪口制退器。完整自由改枪系统不属于首阶段范围。

### 6.2 射击判定

- 枪械使用服务器确认的即时命中判定，以保证近中距离响应；
- 枪口火焰、曳光、弹孔和声音属于表现层，不决定命中结果；
- 破片手雷和其他抛射装备使用独立抛射物；
- 玻璃、薄木板和部分门体支持有限穿透；
- 瞄准、腰射、移动和姿态影响散布；
- 每种武器拥有独立的垂直和水平后坐力。

### 6.3 伤害和治疗

- 头部、躯干和四肢使用不同伤害倍率；
- 护甲降低躯干伤害，并随受击损坏；
- 生命不会自动完全恢复；
- 医疗包恢复生命，护甲板修复护甲；
- 合作模式阶段增加倒地和队友救援；
- 伤害、弹药消耗和物品使用由服务器权威确认。

### 6.4 战术装备

首章包含：

- 破片手雷；
- 烟雾弹；
- 医疗包；
- 侦察无人机。

侦察无人机只能在限定时间和距离内标记敌人，不能持续透视整个地图。

## 7. 敌人 AI

### 7.1 敌人类型

1. **步枪兵**：基础单位，使用掩体持续射击；
2. **突击兵**：使用冲锋枪和手雷接近玩家；
3. **精确射手**：占据高处或长视野位置进行压制；
4. **无人机单位**：执行侦察或攻击，迫使玩家改变位置。

### 7.2 行为状态

基础状态流为：

`巡逻或守卫 → 发现异常 → 搜索 → 掩体交火 → 包抄或呼叫增援`

AI 必须遵守以下限制：

- 未获得合理感知信息时不能直接知道玩家位置；
- 搜索使用最后已知位置和声音线索；
- 包抄路线必须通过导航系统验证；
- 增援由任务或区域预算限制，不能无限生成；
- 不同难度主要调整反应速度、命中能力、协同频率和补给，而不是简单增加生命值。

## 8. 游戏模式

### 8.1 任务撤离

完成多阶段任务，携带关键物品到达撤离点。支持单机与合作，后续可加入敌对玩家。

### 8.2 据点进攻

攻击或防守城市关键区域。支持 PVE 推进战、合作和阵营 PvP。

### 8.3 生存防守

在有限资源下抵挡逐渐增强的敌人和无人机。支持单机、合作、波次和积分规则。

### 8.4 开发顺序

1. 单机任务撤离；
2. 使用同一地图增加据点进攻和生存防守；
3. 2–4 人合作；
4. 阵营 PvP；
5. 玩家与 AI 同场的综合模式。

## 9. 联网架构

- 单机模式由本机同时承担服务器职责；
- 初期合作模式采用房主主机；
- 大型 PvP 使用专用服务器；
- 服务器确认伤害、弹药、库存、任务目标、胜负和关键交互；
- 客户端负责输入、预测和表现，不得独立决定关键结果；
- 角色、武器、任务和模式状态必须支持网络复制；
- 合作断线恢复和匹配系统不属于首个单机章节的验收范围，但接口必须预留。

## 10. 第一章：城市封锁线

第一章预计持续 30–45 分钟，采用线性主线加局部多路线结构。每个主要区域允许正门、侧翼或维护通道等选择，关键战斗结束后路线重新汇合，以控制制作规模。

### 10.1 章节流程

1. **外围检查站，5–7 分钟**
   - 教授移动、视角、瞄准、射击和侦察；
   - 与基础巡逻队首次交火。

2. **地下停车场，6–8 分钟**
   - 低光环境与近距离战斗；
   - 使用战术灯、烟雾弹和侧翼路线。

3. **商业中心，10–15 分钟**
   - 营救技术人员；
   - 获取加密数据；
   - 经历多层室内外战斗。

4. **地铁设施，6–8 分钟**
   - 恢复设施电力；
   - 遭遇无人机和敌方增援。

5. **屋顶撤离，5–7 分钟**
   - 防守撤离点；
   - 等待撤离载具到达；
   - 携带数据完成章节。

### 10.2 任务目标

- 主要目标：营救技术人员并取得加密数据；
- 次要目标：关闭敌方防空设备；
- 可选目标：寻找失联侦察小队；
- 最终目标：携带数据抵达屋顶撤离点。

可选目标影响任务评分和奖励，但不阻止主线通关。

### 10.3 节奏

章节循环为：

`观察和侦察 → 选择路线 → 短时高强度交火 → 搜集和补给 → 推进任务`

### 10.4 检查点与失败

- 完成每个主要区域后自动保存检查点；
- 玩家死亡可从最近检查点恢复；
- 关键任务人物死亡或关键数据被摧毁会触发任务失败；
- 存档记录章节进度、任务状态、玩家装备和必要世界状态；
- 损坏或不兼容存档不能导致游戏崩溃，游戏应提示并允许重新开始章节。

### 10.5 地图复用

首章完成后，通过调整出生点、封锁区域、补给和目标位置，把同一张城市地图扩展为据点进攻和生存防守模式。

## 11. 难度

首阶段提供：

- **普通难度**：明显目标提示、适量敌人和较充足补给；
- **战术难度**：敌人反应更快、补给更少、HUD 信息减少。

后续增加自定义难度，允许分别调整敌人伤害、数量、提示、友军伤害和资源数量。

## 12. 画面与素材流程

### 12.1 制作阶段

1. 使用简单几何体建立灰盒地图；
2. 验证路线、视野、战斗距离和任务节奏；
3. 使用合法授权的免费与付费素材替换灰盒；
4. 统一材质、色彩、标识、磨损和灯光；
5. 在独立显卡工作站上增加 Lumen、Nanite、特效和后期处理；
6. 针对低、中、高画质档位分别优化。

### 12.2 素材合规

- 每个第三方素材必须记录来源、许可证、作者或供应商及允许用途；
- 禁止提交来源不明或未经许可的素材；
- 允许修改的素材可以统一风格，但不得作为独立素材包重新分发；
- 项目必须保留素材清单和许可证证据；
- 正式发行前对全部第三方内容进行许可证复核。

## 13. 界面、音效与无障碍

### 13.1 界面

- 主菜单；
- 模式选择；
- 章节和难度选择；
- 装备界面；
- 设置界面；
- 生命、护甲、弹药、任务和小地图 HUD；
- 任务结算界面。

### 13.2 无障碍和设置

- 键位自定义；
- 字幕；
- 色盲辅助；
- 视野范围设置；
- 第一和第三人称独立灵敏度；
- 音量分组；
- 低、中、高画质预设。

### 13.3 音效

- 室内外枪声和空间混响；
- 不同地面材质的脚步声；
- 敌人语音、无线电和任务播报；
- 重要语音全部提供字幕；
- 音效负责提供位置、距离和危险信息，不仅用于装饰。

## 14. 性能与设备策略

当前开发设备为 Intel Core i7-1185G7、32GB 内存和 Intel Iris Xe 集成显卡。该设备用于轻量原型、代码、数据配置和低画质灰盒测试，不用于最终 3A 视觉验收。

### 14.1 当前设备策略

- 使用低分辨率和低画质；
- 关闭高消耗光照和后期效果；
- 控制编辑器同时加载的区域和素材；
- 优先验证玩法、任务和代码正确性。

### 14.2 发布目标

- Windows 64 位独立程序；
- 1080p、稳定 60 FPS 为主要目标；
- 提供低、中、高画质档位；
- 高性能硬件可选择 1440p 或 4K；
- 最终 3A 视觉验收在具有 DirectX 12 独立显卡的设备上完成。

性能目标必须通过实际目标硬件测试确认，编辑器帧率不能替代打包版本测试。

## 15. 错误处理与恢复

- 任务系统必须拒绝无效状态转换，并记录可诊断日志；
- 缺失非关键素材时提供安全回退，不阻止关卡启动；
- 缺失关键地图或任务定义时阻止开始并显示可理解错误；
- 联机操作超时或断开时返回菜单并保留安全的本地设置；
- 存档写入采用临时文件和替换策略，避免中断造成主存档损坏；
- 任何错误提示不得显示访问令牌、用户隐私或本地敏感路径。

## 16. 测试策略

### 16.1 自动检查

- 核心 C++ 编译；
- 模块加载；
- 资源引用有效性；
- 基础关卡启动；
- 武器射击、换弹和弹药状态；
- 伤害和护甲计算；
- 任务状态转换；
- 检查点保存与加载；
- 网络复制的关键状态。

### 16.2 人工验证

- 第一和第三人称切换；
- 全章节任务流程；
- 敌人感知和战术行为；
- 路线和检查点；
- 键鼠操作与设置保存；
- 字幕和 HUD 可读性；
- Windows 打包版本性能；
- 不同画质档位的稳定性。

## 17. GitHub 工作流

- 不直接在 `main` 上开发功能；
- 每项功能使用独立分支；
- 完成测试后创建 Pull Request；
- Pull Request 通过检查和审阅后合并；
- Unreal 大型二进制资源使用 Git LFS；
- `.superpowers/`、缓存、编译产物、本地设置、密钥和临时文件不得提交；
- 每个重要里程碑生成可运行的 Windows 构建，并保留对应提交记录。

## 18. 范围边界

### 18.1 首阶段包含

- Unreal Engine 5 和 Lyra 基础工程；
- Windows 64 位打包；
- 第一和第三人称切换；
- 单机 PVE 任务撤离；
- 一张现代城市战区地图；
- 一段 30–45 分钟章节；
- 三把武器；
- 四种战术装备；
- 四类敌人；
- 基础部位伤害和护甲；
- 检查点和本地存档；
- 菜单、HUD、设置和字幕。

### 18.2 首阶段不包含

- 开放世界；
- 载具驾驶；
- 大规模建筑破坏；
- 完整自由改枪；
- 2–4 人在线合作的正式发布；
- 大规模 PvP 和专用服务器部署；
- 匹配、排行榜和商业化系统；
- 多章节完整剧情战役。

这些内容属于首章稳定后的后续阶段。

## 19. 首阶段验收标准

首阶段完成时必须满足：

1. 玩家可以从主菜单进入“城市封锁线”；
2. 章节可从开始连续完成到屋顶撤离，目标时长为 30–45 分钟；
3. 玩家可以在第一和第三人称之间切换；
4. 三把武器均支持射击、瞄准、换弹、弹药和伤害；
5. 四种装备均具有明确可验证的作用；
6. 四类敌人能够执行其定义的基础战斗行为；
7. 主要目标、次要目标和可选目标能够正确结算；
8. 检查点可以保存和恢复必要进度；
9. 普通和战术难度均可选择；
10. 游戏可以打包为 Windows 64 位独立程序；
11. 目标测试设备在 1080p 对应画质档位下以稳定 60 FPS 为优化目标；
12. 不包含未授权素材、访问密钥或个人敏感配置。

## 20. 主要风险与应对

### 20.1 当前显卡性能不足

**应对：** 当前电脑只做低画质功能原型；最终画面和性能在独显电脑上完成。

### 20.2 首章规模过大

**应对：** 使用五个明确区域、路线重新汇合和素材复用控制规模；先完成灰盒全流程，再提升画面。

### 20.3 第一和第三人称增加动画成本

**应对：** 统一角色状态和武器逻辑，仅分离表现层；先保证基础动画完整，再增加细节。

### 20.4 过早开发多人导致进度缓慢

**应对：** 首章只发布单机，但关键规则遵守服务器权威和复制边界；多人界面、匹配和部署后置。

### 20.5 第三方素材风格不统一或许可不清

**应对：** 建立素材清单，统一材质与标识，并在导入和发布前执行许可证检查。
